# 连接模型表单保留未提交输入

Round 32 独立前端审查复现：从 Boss 表单打开连接设置，输入自定义模型和思考强度，点击返回项目后再打开，输入被重置为默认值。任务本身草稿没有丢失。实际 App 的隔离交互测试失败，且所有模型验证/任务提交请求均未发出。

根因是 ConnectionVerificationForm 使用组件局部状态，而 Boss 的返回操作会卸载该组件。本轮让现有 App 所有的连接验证 store 同时持有未提交草稿；表单卸载和不同设置入口间切换都不清除它。不新增浏览器持久存储键，刷新页面后的未提交草稿保留不在本轮范围内。

未提交草稿与已发出的 pending 请求保持不同身份。修改草稿不能替换原请求的模型、强度、key 或 jobId；正在验证/结果未确认时字段继续锁定，重试仍沿用原请求。重新挂载时优先显示原 pending 请求；无 pending 时恢复当前草稿。终态 job 不应覆盖用户随后编辑的值。

连接选项延迟返回按字段初始化，不能覆盖用户手动输入的模型、空值或选择。只编辑模型时，尚未编辑的思考强度仍需采用服务端提供的有效默认值；不能因为模型被编辑就把尚未选择的 high 当作用户意图。初始化可采用现有首选模型/high 或服务端提供的有效强度。所有打开、返回、关闭和输入操作均不得调用真实模型。验证按钮原有的显式使用额度提示和校验行为保留。

验证：把独立审查的 App 回归加入常规套件并先观察失败；覆盖返回项目/重开、关闭设置后其他入口重开、延迟 setup、pending 结果未知原 key 重试以及成功后编辑草稿。运行完整 web 交互测试、API 请求测试和 web 构建，独立复审。根目录核心代码不在本轮修改范围内。

最终验证：常规 App 回归先失败后通过。初版通过测试后，独立复审另外复现了“只编辑模型，未编辑的强度未采用服务端默认值”问题；修复为按字段初始化，两项补充回归先失败后通过。最终针对测试 33 项、完整 web 测试 360 项、API 请求测试 19 项及网页构建均通过；独立六项交互复核全部通过，无遗留阻塞发现。初次 API 运行的 4 项本地回环连接 EACCES 失败单独保留，允许回环连接后的复核通过，没有删除断言或调用真实模型。

日志、退出码、初次失败及修复后的源码哈希保存在忽略目录 `data/verification/frontend-audit-round32/implementation/`，独立复审证据在同级 `review/`。本轮是实际组件交互和请求生命周期验证；浏览器自动操作因工具无法可靠确认 Windows 浏览器网址而停止，没有目视截图验收。
