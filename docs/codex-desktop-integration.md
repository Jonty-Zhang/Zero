# Codex 连接方式

Zero 当前通过本机 Codex CLI 运行组件调用 Codex。这里的 CLI 是程序调用方式，用户在 Zero 网页里派发任务，不需要逐条操作终端。模型、思考强度和任务权限由已验证的绑定及任务计划决定。

## 桌面版能否接入

可以围绕官方 [Codex App Server](https://developers.openai.com/codex/app-server) 协议构建更深入的接入：它提供会话、流式事件、认证和审批接口。该协议允许创建独立的 Codex 会话，但这不能证明第三方程序可以接管一个已经打开的桌面窗口，或直接拥有桌面会话的登录、工具、插件及历史。

**本版本尚未启用 Codex App Server，也不提供“桌面版已连接”的状态或切换开关。** 安装、打开 Codex 桌面版，不等于 Zero 已经有可执行的 Codex 模型。

2026-10-27 的协议试验发现，不能直接把现有 `codex exec` 的只读验收配置隔离参数移植到 App Server。仅设置只读文件沙箱或拒绝工具审批，也不能证明项目配置、技能和插件全部隔离。因此这一轮保留既有通道，没有发布隔离条件未验证的实现。

完整接入需要先验证：

- 配置来源和工具权限受到 Zero 的执行、规划及验收边界约束；认证不通过复制用户的个人配置实现。
- App Server 的模型绑定独立验证并钉住运行组件版本，不能复用 CLI 验证记录。目录中的模型不等于账号拥有访问权限。
- 模型改道、结构化输出、取消、超时和子进程退出有可复现的证据；失败或中断不能记为验收通过。

## 网页中的状态

“可用”表示服务报告有可用的已验证模型。“待验证模型”表示运行组件已检测到，但尚未有通过真实调用验证的绑定。“运行入口不可用”表示运行组件未能启动，应检查完整技术详情、入口路径及工作目录；它不一定表示软件未安装。

“尚未检测”“检测中”和“状态未知”都不代表模型可用。刷新连接状态只重新读取 Zero 服务的结果，不会登录账号、安装程序或自动调用模型。修改服务端绑定后，按[服务端说明](../src/server/README.md)重启 Zero，再刷新状态。

若网页仍显示旧界面，刷新当前地址即可。HTML 会重新校验，带哈希的静态文件保留缓存；页面不会为了更新而自动刷新并丢弃尚未提交的任务草稿。
