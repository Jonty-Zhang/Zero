# Stage objectives and semantic agent relay

The second audit found that executionStages selects models but cannot assign their work, while RunResult.final is discarded. A fingerprint proves which checkout a successor receives; it cannot explain why the predecessor changed it or what remains.

Keep the existing serial worktree execution and all validation/review/recovery gates. Add an optional `objective` to execution stage submissions (trimmed, 1–4,000 characters). Legacy selection-only stages remain valid. The public API and CLI use the same field. Persist it in the task payload, return it in task details, and show it in the stage editor and submitted plan. Give each writer its stage objective together with the unchanged overall task and acceptance criteria. Explicitly retain overall criteria and reviewer-requested fixes as authoritative during revisions. Route selection must contain only harness/model/reasoningEffort; objective is task context, never a selection field.

Preserve each executor's final text as optional `executorSummary` in attempt metadata and HandoffV1. Normalize whitespace boundaries and bound it to 3,000 UTF-16 characters and 8 KiB UTF-8 without splitting a Unicode code point. Do not parse arbitrary model prose into trusted decisions, completion, checks, paths, or provenance. It is an executor claim rendered as plain text and included in the already provenance-checked, bounded untrusted handoff context. Empty/missing finals remain compatible. Prompt executors to summarize changes, decisions, remaining work and risks for the next agent. Archived reports and task details expose this evidence. Existing observed checks, fingerprints, and independent review remain authoritative. Persist before stage finalization so recovery can reuse it; failed/quota attempts cannot become successful prior-stage evidence.

The web UI must make ordered stages useful: editable goals, understandable plan ordering, and visible untrusted executor summaries. Continue auditing actual UI/API interactions and fix reproducible lifecycle or data-loss bugs separately. Do not change production configuration or run paid provider probes merely to produce a green demonstration.

Acceptance: stage objectives survive submit/store/reopen/API/detail and reach the intended writer; model routing and legacy stages remain compatible. A real two-adapter Git-backed worker regression proves one executor's final reaches its successor with provenance and untrusted labeling. Oversized Unicode, absent finals, forged or mismatched handoffs, review revisions and existing recovery behavior remain bounded and fail closed. Browser validation covers authoring/reordering/submitting stage goals and reading summaries on desktop/mobile. Commit and push incremental verified changes to the existing PR.
