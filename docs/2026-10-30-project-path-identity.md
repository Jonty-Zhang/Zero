# 同一项目目录的接力身份

Round 28 组件与真实 API 客户端回归确认：已验收项目继续表单中，仅将 Windows 目录反斜杠改成正斜杠或补尾斜杠，就不再带成果 SHA；高级表单改发 HEAD。首次提交结果未知后做同样编辑，还会换请求摘要与幂等标识。默认原路径不编辑时不触发；普通浏览返回 canonical 路径也通常正常。

本轮实现者选择复用既有只读 folders API 的 realpath 结果确认目录身份，不新建后端端点、不执行快照，也不对整个 Windows 路径盲目转小写。只有服务确认的 canonical 路径与任务记录中的原 canonical 路径相同，才沿用验收 SHA。真实不同目录、区分大小写的不同目录、创建新目录和不同成果 SHA 必须继续隔离。

前端新增共享的目录确认 hook，Boss 和高级表单使用同一结果。原始路径完全相同、普通项目、create=true 或非法来源 SHA 不发确认查询；有效 continuation 的不同路径表示通过 api.folders 确认。结果必须绑定当前路径、创建开关和来源身份；旧请求中止或晚到不能覆盖新目录。确认进行中、失败或响应非法时不得提交未确认的 HEAD，也不得静默生成新请求。错误提供重试检查入口，不创建任务。

Boss 草稿摘要与固定起点 payload 使用已确认的 canonical 路径；因此等价编辑后仍能确认原未决提交，保留原 payload 对象和原请求标识。高级表单显示当前实际起点；确认中不能把 HEAD 当作已确定值。切换连接设置、高级往返和取消/普通新建仍保持已有语义。普通新项目的准备与快照流程不变。

验收包括 Boss/高级实际提交、同目录不同表示的 SHA 保留、未知响应后的 body/key 复用、真实不同目录和不同 SHA 隔离、旧确认晚到与失败重试，以及仓库内真实 Windows 目录/API 的只读确认。全程假模型，不读个人配置，不修改仓库外文件。

完成验证记录位于本地忽略目录 `data/verification/boss-path-round28/`：先观察五项主流程回归失败，另对非法目录响应及空错误消息观察失败后修复。最终网页 350 项、客户端 API 19 项通过，核心及网页生产构建通过；相关服务 16 项通过，中断恢复后新增真实 HTTP 目录身份测试再次通过。该 HTTP 测试包含当前目录大文件、不同真实目录、无效路径以及不生成 Git/快照的断言。

独立复审最终 18 项全部通过，生产源码前后哈希一致；复审发现的空错误消息绕过确认状态问题已修复并保留回归。真实 API 客户端测试确认等价路径编辑后复用原请求正文、幂等标识及未决 payload。恢复本地服务后 HTTP 200，HTML 与最终网页构建一致；未向实际任务队列提交测试目标。此次界面证据为组件交互测试，不代表截图或真实模型执行验收。
