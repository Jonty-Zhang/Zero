# 从验收成果继续项目

完成页目前只提供独立成果目录，用户需要手动重新选目录。若误选原项目并使用 HEAD，下一任务不会自动包含上一任务尚未合并的成果。这与连续向 Boss 派发项目工作之间存在操作缺口。

本轮由实现者选择增加“继续这个项目”：仅在 Boss 任务已完成、原项目路径存在于任务数据且服务提供完整成果提交标识时可用。点击只打开下一任务表单，不直接启动模型或提交任务。保留原项目路径和用户的 Boss 偏好，下一步目标留空，由用户填写；起点固定为上一任务的成果提交，而不是原项目当前 HEAD 或可能被编辑过的旧成果工作区。

沿用既有 POST /api/tasks 的 baseRef 验证和可靠重试协议，不增加自动合并、推送、权限或新的执行恢复分支。表单明确显示“从上次验收的成果继续”。切换到其他文件夹时停止沿用原成果提交；返回同一路径可恢复原固定起点。任务 payload 与不确定重试身份都必须包含实际生效的 baseRef，不能在切换高级表单后悄悄恢复为 HEAD。

继续任务从该提交的文件开始；不将历史 Boss/顾问讨论重新伪装成当前用户指令，也不宣称继承供应商会话。新目标由 Boss 重新研究、规划、委派和验收。原任务保持不变，新任务仍使用独立工作区。

验证包含界面点击、草稿与连接设置切换、固定提交提交与重试、换目录和高级表单；隔离真实 Git/SQLite/HTTP/Worker 验证上次成果进入下一任务，即便原项目 HEAD 后来推进也不改变起点。缺少成果提交或未完成的任务不能提供该入口。全程假模型，不读取个人 agent 配置。

实现后的验证记录位于 `data/verification/boss-continuation-round26/`（本地忽略目录）：全量网页 312 项、前端 API 19 项、既有项目目录/提交幂等服务回归 18 项通过，核心及网页生产构建通过。新增真实工作流测试完成两轮任务，额外修改旧成果目录并推进原分支，下一任务仍从验收提交创建；精确重试复用原任务，变更基线的同键请求返回 409，不存在的提交返回 400。独立复审另跑 92 项界面与 19 项 API 测试，未发现阻塞问题。以上使用假模型验证执行协议，不代表真实供应商调用已验证。
