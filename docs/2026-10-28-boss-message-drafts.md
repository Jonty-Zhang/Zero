# 任务详情切换时保留补充要求

## 问题与复现

Boss 补充消息原来保存在任务详情组件的局部状态中。关闭详情、查看另一个任务、再打开原任务，未发送的原文会丢失；发送超时后保留的文字也一样会丢失。实际 App 导航的两个回归场景在修复前失败，而同一任务的普通状态轮询控制场景通过，因此缺陷来自组件卸载后的状态生命周期。

## 改动

App 实例持有按任务 ID 分隔的消息编辑器，任务详情仅订阅当前任务的草稿、发送状态、错误和回执。关闭详情或切换任务不会清除这些状态，也不取消已经发出的请求。

同一任务发送前同步加锁，离开再打开仍显示正在发送，重复提交不会启动第二个请求。不同任务可以各自编辑和发送。请求完成只更新所属任务，且必须与当前操作标识匹配；成功仅在编辑版本和原文均未变化时清空输入，旧结果不能清掉后续编辑。

失败和超时保留原文。重试继续调用现有 API，沿用其按任务和内容识别不确定请求的幂等机制。成功回调携带任务 ID，只有当前打开的同一任务才刷新详情；刷新异常不撤销已经确认的回执。

验收或额度暂停关闭消息准入时，草稿仍保留并禁止新提交。该改动不绕过服务器的要求封存与消息准入规则。

## 范围

保证当前 App 实例内的详情关闭、任务切换与页面导航保留。未把补充要求明文写入 localStorage 或 sessionStorage，也不承诺浏览器刷新、关闭标签页或重启应用后恢复草稿。真实模型执行和后端验收协议不在本轮变更范围。
