# 多阶段规划的交接预算

真实 Worker、BossOrchestrator 和假模型复现：合法 16 阶段项目，约 8k 原文、20 项各约 1k 标准，零用户对话消息，完成第 9 个执行阶段后因 256 KiB 规划对话上限失败。每份机器 handoff 重复原任务及标准约 28,874 字节，实际对话只有 3,776 字节，最终检查尚未开始。

本轮选择把机器 handoff 作为独立的 BossPlanContext 证据字段，不再伪装为 consultant 对话消息。Worker 仍从持久 Store 提取最近 16 份记录。Boss 为规划和顾问输入使用已有 renderHandoffContext 生成的有界、不可信投影，保留来源、工作区指纹、执行者自述及后续注意事项；不重复 handoff.task 中的原文与验收标准。完整记录继续保存在 Store/报告。

真实用户/负责人/顾问对话的现有 256 KiB 校验不放宽、不截断。原始任务、所有验收标准和用户原话保持完整，不改成模型摘要。机器证据有独立上限，若因 JSON 编码等触及总预算，只省略较老的机器投影并明确数量，不能悄悄删掉用户要求；预算按最终序列化字节验证。规划、咨询都必须得到同样的机器证据语义。

验收必须让原失败输入完整执行 16 阶段、真实最终检查和独立验收直至 DONE，并检查每次规划保留原文/标准以及有效交接投影。还需覆盖机器证据 Unicode/转义膨胀、无 handoff、超限用户消息仍拒绝、咨询和已有返工恢复。所有模型使用假适配器，仅操作本仓库。

本地验证证据位于忽略目录 `data/verification/boss-handoff-round30/`。原输入先复现超限失败；修复后完整 16 阶段通过真实检查、TaskReviewer 验收并产生 DONE 与结果提交，增强版逐次核对规划中的全部要求、来源和指纹，也通过。独立构建及 31 项测试通过；额外对抗验证保留约 240 KB 对话原文，并确认最终机器 JSON 恰好 131,072 字节时不省略，超出 1 字节时只省略最老一项且计数准确。

原完整核心测试在受限沙箱运行，结果保留为 929 项中 791 通过、137 失败、1 取消，不能记为整套通过。文件链接、进程树及本地 HTTP 权限限制导致失败；其中一个 HTTP 用例因未收到请求而挂起，核对 PID、父进程、命令与启动时间后仅终止该测试子进程，保留失败记录。随后按失败清单在正常权限下复核：10 组共 187 项全部通过，逐项名称对照覆盖全部 138 个失败/取消条目，无重名或未匹配项（`recheck-reconciliation.json`）。未以改变产品权限或跳过断言解决测试失败。

测试残留的确切子进程已核对并清理，原始失败日志、分类和清理回执保留。生产源码冻结哈希与独立复审一致；发布检查仅删除了新增测试末尾的多余空行，另存格式回执。服务在核对空闲与进程身份后更新，HTTP 200 且网页构建一致。本轮没有真实模型调用或截图验收。
