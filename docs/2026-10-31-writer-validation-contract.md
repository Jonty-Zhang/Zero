# 实现者可见的验收命令

Round 29 审查发现：Worker 把 Boss 计划的 checks 交给路由和审查者，却没有放入真正实现/返工 agent 的 RunRequest。失败返工简报只有检查编号、状态、退出码及可选进程错误。内联产物断言可能只存在于 checks.argv，因而执行者无法知道具体判定条件或复现失败命令。

本轮选择在共用 writer 请求边界传递当前完整检查定义，以 JSON 保存 argv 的参数边界，说明这些命令由 Zero 在真实工作区直接执行、不使用 shell。其作用是公开当前验收合同，不扩大执行者权限、不替代独立检查或审批，也不把工具输出当作用户指令。失败简报通过检查编号关联这份合同，不重复内联命令。初次执行、检查返工、审查返工与额度恢复共用这个边界。

验证采用真实 Git/SQLite/Worker 与假模型：现有两种返工场景新增断言，证明实现与返工请求收到 Boss 生成的精确 argv；先观察缺失导致失败，再运行完整 Boss、跨 agent 接力和返工额度恢复回归。命令原有执行及验收判定逻辑不改变，不读取日志或个人配置。

本地证据在 `data/verification/boss-handoff-round29/`：两项回归先失败；Boss、用户要求、接力、同代与重启后返工额度恢复共 23 项通过。独立复核建议避免失败简报重复内联命令后，最终单一合同版本重新构建，并再跑两种实现/返工场景，均通过。服务在核对空闲及进程身份后更新，HTTP 200。

本轮只公开现有检查命令，不宣称传递了完整 stdout/stderr 诊断，也没有修复另行复现的长期规划 handoff 重复内容超限问题；后者的真实 16 阶段任务失败证据保存在同一验证目录，留待下一轮处理。所有验证使用假模型。
