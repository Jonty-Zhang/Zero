# GPT-6 Astra high 独立复审

用户指定以 GPT-6 Astra、high 推理强度重新审查。新建独立子 agent，以干净的 `f4ca1da` 为基线，读取第二轮全部生产代码变更，并追踪 worker、持久化、HTTP、适配器和网页的实际调用路径。审查确认三项 P2，未确认 P1；这不代表其余缺陷已经穷尽。

| 确认的问题 | 修正与回归 |
| --- | --- |
| 超大协议行的身份被流式结果覆盖或完全丢弃，错误模型仍可能显示执行成功 | 合并诊断与流式身份、冲突和错误证据，流式结果仍独占 final。超大 JSON 行采用有界投影：扫描完整字符串转义，省略大正文，保留正文前后的身份/错误字段；投影绝不充当 final。无法验证结构或元数据则失败，后续 final 不能清除错误。真实子进程覆盖 270 KiB、3 MiB 及字段位置；补充分块、UTF-8、非法转义、元数据与结构超限测试 |
| 结构化 `insufficient_quota` 等账户错误码被丢弃，仅剩“Quota exceeded”文字后错误进入自动等待 | 保留 provider 错误的顶层/嵌套 code 与错误类型；无法验证完整协议时不能建立额度恢复。有效的 provider 失败终态仍可在没有成功 final 时按既有策略等待，不受大工具日志影响 |
| 审核或提交边界已检测到工作树变化，失败任务的旧绿检查仍标为当前通过 | `failed` 任务的 `completed` 批次保守转为历史，保留所有原始检查与任务失败原因。失败批次的当前失败 gate 不变，不修改数据库证据或 DONE 门禁。真实 Git 流程经 HTTP 验证审核修改、审核进程失败及提交前晚到修改 |

大行投影最多 256 KiB，每个字符串最多 4096 个原始字节；大字符串仅在投影中替换为省略标记。身份、session 或 provider 错误字段本身被省略时拒绝认定完整协议，不能降级为 selector-only 成功。保留正常最终答复的既有单行上限；没有可信最终答复或 provider 错误终态时仍明确失败。

复现与验证使用隔离 Git 工作区和本地 Node 子进程，没有调用真实付费模型或修改生产配置。父代理独立重跑了全部三项复现；审查 agent 又复测了大行修复、账单错误和 HTTP 检查展示，并测试了转义及有界失败行为。定向回归 49 项通过，另有 3 项真实 Git/HTTP 回归通过；前端 18 项、客户端 API 10 项、类型检查和生产构建均通过。完整测试及精确提交 CI 的持续结果见 [PR #1 检查](https://github.com/Jonty-Zhang/Zero/pull/1/checks)。

修复复审中还发现并拦截一项中间版本回归：历史可恢复错误不能替代后续无法读取的最终答复。最终规则要求进程明确失败且非零退出，并且完整 provider 错误出现在最后一次超大事件的有效投影中或其后；永久协议错误优先。新增两项真实子进程回归先失败后通过。Astra 最后独立复验“早期 transient error 后大 final / 早期 quota 后大 final / 大 tool 后有效 quota / 不可验证元数据后 quota”四种顺序，确认无遗留 P1/P2；此结论限于此次审查范围。

原审计中的真实 provider、DSH、自然额度耗尽与任意崩溃边界限制仍适用。详见[第二轮审计](2026-10-17-semantic-relay-audit.md)。
