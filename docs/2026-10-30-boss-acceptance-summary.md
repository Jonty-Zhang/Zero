# Boss 验收摘要的提交边界

生产入口此前在模型返回后立即发送 `验收：pass` 等讨论消息，随后 Worker 才比较审核前后快照、验证进程结果并提交验收证据。如果快照发生变化或验收落库被拒绝，这条通过消息仍会留在讨论区，与真实结果矛盾。

本轮将摘要移入 `TaskStore.finishPackageReview` 的事务。只有当前审核包、快照、有效租约与归属、模型身份、取消状态和结构化结果全部被接受后，才与验收结论、尝试状态及定向答复一起提交。摘要写入失败会回滚整笔事务；重放已结束尝试不会追加第二条。摘要标识为“验收通过”“需要修改”或“验收受阻”，附审核包和尝试来源，不附用户消息标识，因此不会伪装成逐条答复。非 Boss 任务不产生讨论摘要。

生产入口通过 `createConfiguredTaskReviewer` 继续按调用时配置选择验收模型，并固定 Boss 任务的持久负责人。该封装只返回模型提议，不发表讨论消息；用户要求来自已封存快照，不再拼接当前讨论到任务提示中。Worker 的校验、恢复及返工入口保持不变。

本轮也补齐上轮遗漏的一组旧假模型集成测试：输出须包含准确覆盖封存目标的 `userMessageReplies`，并验证关联答复只保存一次。原有消息原文、回执、额度、返工、跨重启和交付断言保留。完整测试改用实际生产验收封装，额外确认模型返回时没有提前发表消息，最终每条摘要都能找到已提交的验收结论。

验证结果：存储、额度提交、Reviewer 要求及服务入口相关回归 181 项通过；实际生产验收封装的六个完整 Worker 场景全部通过；独立复审另行编译并运行 61 项相关检查，未发现阻塞问题；前端 286 项与请求生命周期 18 项通过，核心构建通过。上一轮 GitHub Linux 完整套件的六个失败均来自上述遗漏的旧假模型输出，本轮已复现后补齐并全文件重跑。

全部测试使用隔离项目和假模型，未调用真实供应商模型。模型返回质量及供应商完成到本地事务之间的原有不确定窗口，不在这些结果的证明范围内。
