# 固定成果起点不重新扫描原目录

Round 27 真实 HTTP/Worker/Git 回归复现：完成首个 Boss 任务后，在原目录新增 10 MiB + 1 字节的本地文件，再用已验收提交作为 baseRef 创建后续任务，服务返回 400（文件过大）。当前网页在 POST 前还调用一次 prepare，存在同样阻塞。已选定的成果不依赖原目录当前文件，但这两个入口都强制建立了未使用的当前快照。

本轮实现者选择沿用现有基线协议，分开两种含义：无显式 baseRef 的普通 Boss 项目继续准备当前文件夹；有显式非空 baseRef 的 Boss 项目只读验证现有仓库根目录和该提交，不执行 init、文件枚举、hash-object、commit-tree 或 update-ref。路径必须是实际 Git 根目录，不能把子目录偷偷提升到父仓库；拒绝无 Git 目录和 .git 符号链接，允许正常 linked worktree 的 .git 文件。

网页在固定 continuationBaseRef 生效时直接提交原目录和成果 SHA；切换目录或创建新目录后仍走普通 prepare。未知结果重试继续复用既有精确 payload 与请求身份。高级配置、普通项目的快照隐私规则、验收、模型路由和恢复协议不变。本轮不调用真实模型，不读取个人配置。

验证要求：先观察大文件复现失败；网页测试证明准备接口即使不可用也不影响固定起点提交，且换目录/新建仍准备；服务测试证明固定基线不会产生快照或修改 HEAD/index，并拒绝错误路径/基线；真实 Worker 完成第二任务且未混入后来的本地文件。最后跑相关回归、构建、独立复审、安全更新本地服务、提交并回读 GitHub main。

本地证据位于 `data/verification/boss-recovery-round27/`（忽略目录）。真实接力测试先得到预期的 400 错误；新增三项 HTTP 回归也先失败，其中一项确认无效固定起点原先会给普通目录创建 Git。修复后最终相关后端 29 项、全网页 318 项、API 19 项通过，核心和网页构建通过。独立前端复审另跑 98 项；独立后端复审另跑最终四项 HTTP、既有目录回归，并补测 `.git` junction 拒绝和 Git 环境污染隔离，未发现阻塞问题。

固定起点的只读性由 HEAD、refs、对象数量、索引与本地配置的前后比较验证；linked worktree 也受覆盖。本轮没有真实供应商调用。直接页面观察因可用 Chrome 窗口最小化未完成，不将组件测试或 HTTP 检查称为截图/视觉验收。

最终完整服务回归覆盖 25 个测试文件、224 项，全部通过，包括跨仓库接力、重启、目标返工和可靠重试。本地服务安全更新后 HTTP 200，返回 HTML 与最终网页构建完全一致；未向生产任务队列添加测试任务或启动模型验证。
