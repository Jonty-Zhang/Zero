# 2026-10-24：任务取消失败提示与当前状态

## 问题与修复

任务详情在轮询到已完成、失败或需要人工恢复后，仍可能显示先前取消请求的失败提示。即使轮询先加载了新状态，旧取消 POST 的迟到 503 也会重新加入提示，让已经结束的任务继续显示可操作的旧错误。

现在按钮和错误提示共用同一个可取消状态判断。当前 pending、running、reviewing、revision、waiting 任务的取消错误仍可见并可重试；任务退出这些状态后隐藏该动作的旧错误。此改动只约束反馈显示，不改变取消请求、服务端状态或原有错误记录。

## 验证

新增八项真实 App 与 API 客户端控制，只替换 fetch 返回值。三个不可取消状态分别覆盖错误先到、503 迟到，共六个回归；另两个控制验证当前错误可重试，以及关闭旧抽屉、打开另一任务后不串反馈。同一测试在旧 App 六项失败、两项通过，实际退出 1；修复后 8/8，实际退出 0。
